## 0. Карта проекта — прочти это первым

**Что за проект.** Русскоязычная AI-DnD игра: живой фронтирный городок, у каждого жителя
разум/память/дела. Веб (FastAPI + один play.html). LLM — DeepSeek (профиль `deepseek`).

**Модули** (`src/aidnd/`):
- `citygraph/` — граф города (генерация, A*, визуал). НЕ трогать генератор без нужды.
- `worldgen/` — стор (`store.py` = WorldStore, sqlite), enrich зданий, пулы.
- `mind/` — разум NPC: NpcState (черты/потребности/эмоции/отношения/память),
  `decide_hybrid` (LLM-решения), `apply_actions`, агенды. `llm_agent.py` — промпты.
- `items/` — предметы: фактшит surface(врёт)/hidden(истина), Mod/Gate/Capability,
  `craft.py` (ROLE_RECIPES), item_smith (LLM-ковка).
- `combat/` — бой 5e-lite: `model.py` (Combatant из монстра/NPC/pc, бестиарий 322 —
  `content/bestiary.json`), `engine.py` (Encounter: грид, инициатива, ходы),
  `encounters.py` (подбор по CR+среде), `auto.py` (авторезолв).
- `server/` — `app.py`, `routes_play.py` (ВЕСЬ игровой контур, ~2300 строк),
  `routes_auth.py`+`auth.py`+`usage.py` (email-сессии, лимиты, коды), `db.py` (postgres
  сервиса), `web/play.html` (весь UI одной страницей), `web/landing.html`, `web/login.html`.

**Данные, две sqlite-БД** (не путать!):
- `data/worlds.db` — КОНТЕНТ-ПУЛЫ, коммитится в гит: `people` (900 NPC: механика+персона),
  `building_pool` (599 зданий kind key/res + 100 имён городов kind city_name).
  Рантайм-таблицы в ней ПУСТЫЕ и должны оставаться пустыми.
- `data/live.db` — РАНТАЙМ миров, в .gitignore, НИКОГДА не коммитить: `user_worlds`
  (user_id→world_id,seed), `buildings` (розданные ключевые), `placements`, `items`,
  `inventory`, `pc_state`, `purse`, `flags`, `contracts`, `npc_state`.
  В `routes_play.py`: `_store()` = live.db, `_pool()` = worlds.db.

**Сессии миров.** Каждый юзер → свой мир (`_play_session` — зависимость роутера: cookie →
user → user_worlds → сессия в contextvar). `_S` — прокси-объект над contextvar (код пишет
`_S["city"]` как раньше), `_wid()` — id текущего мира. Без валидной сессии API отдаёт 401;
`AIDND_OPEN_PLAY=1` (дев/тесты) — общий мир 1 без входа. Мир создаётся ИЗ ПУЛОВ БЕЗ LLM:
граф по seed, `_assign_key_buildings` (ключевые из пула по типу-хинту `_SIGNIFICANT[idx]`),
жилые дома — `_res_binfo` детерминированно (не пишутся в БД), имя города из пула,
расселение ВСЕХ 900 (`_fill_from_pool`).

**Философия (нарушение = провал ревью):**
1. НИКАКОГО хардкода геймплейных чисел в коде — все пороги/цены/шансы в таблице `PB`
   (верх routes_play.py), контент — в данных (json/пулы), а не в строках кода.
2. Общие абстрактные системы, не спецкейсы: единый резолвер `_attempt`
   (примитив×манера×гейты), единый Combatant, контракты = предикаты над реальным миром.
3. Игрок — такой же агент, как NPC. Особые ветки «если игрок» — только в UI.
4. Тон — сухой настольный мастер: 1-2 короткие фразы, без фэнтези-пафоса. Промпт `_DM_SYS`.
5. Мир ПОШАГОВЫЙ: время двигают только действия игрока; каждое действие = 1 тик
   (`_world_tick()`); LLM-прослойка только в локации игрока, кэп `PB.live_llm_cap`.

**Запуск и проверка:**

## Задачи. Порядок = порядок исполнения (зависимости учтены)

### T1. Пермасмерть: гибель героя = уничтожение мира ⚑ правило игры
**Решение (SLICE В7.1).** Поражение героя в бою (hp≤0, статус lost — и в логове, и в
дуэли) = СМЕРТЬ. Мир юзера стирается; следующий заход в /play — новый город с нуля
(новый seed). Бегство из боя — легитимное спасение (без смерти). Отдых лечит.

**Реализация.**
- `WorldStore`: метод `destroy_world(world_id)` — DELETE по world_id из всех рантайм-таблиц
  live.db (buildings, placements, items по inventory мира, inventory, pc_state, purse,
  flags, contracts, npc_state) + удалить строку `user_worlds` (юзер получит новый мир и
  НОВЫЙ seed: при пересоздании давать seed = максимальный существующий world_id + 1, чтобы
  город отличался).
- `routes_play.py`: в `_combat_wrapup` и `_duel_wrapup` ветки `lost` → вместо «очнулся у
  ворот»: пометить сессию `_S["dead"]=True`, вернуть `{"death": {"text": <сухая эпитафия
  из данных, не из кода — шаблон в PB или маленькой таблице>, "days": прожито дней}}`,
  вызвать destroy_world, выбросить сессию из `_SESS`.
- Все игровые endpoints при `_S.get("dead")` → `{"dead": true}` (кроме scene, который
  создаст новый мир — см. ниже). Проще: после destroy сессия удалена; следующий запрос
  `_play_session` создаст новый мир автоматически. Проверь, что кэш `_SESS` и `_CUR`
  не держат старый мир.
- UI (`play.html`): полноэкранный оверлей смерти (стиль как #combat): «Тьма.» + эпитафия +
  прожитые дни + кнопка «начать заново» (location.reload()). Показывать по полю `death`
  в ответе combat_act/act.
**Приёмка.** TestClient: проиграть бой → в live.db нет строк старого wid; повторный scene
создаёт мир с ДРУГИМ именем города; UI-оверлей виден (preview-скриншот).
**Ловушки.** items мира: таблица items глобальная по id — удалять только те id, что были
в inventory этого мира. Не убить чужие миры (WHERE world_id строго).

### T2. Боевое время: раунд = 5 секунд (SLICE В1.4/В7.4)
`gt` в минутах. В `Encounter` уже есть `round`. В `_combat_wrapup`/`_duel_wrapup`:
`_gt_add(max(1, enc.round * 5 // 60))` вместо текущей стоимости, плюс в PB:
`"combat_round_s": 5`. Мир (live-тик) во время боя НЕ тикает (уже так — бой не зовёт
`_world_tick`). Приёмка: после боя из ~12 раундов часы сдвинулись на 1 минуту.

### T3. Дальний бой «как в BG3» (SLICE В7.3)
**Механика.** Оружие получает дальность из ДАННЫХ:
- в `combat/model.py` таблица `WEAPON_RANGE = {"лук": 12, "арбалет": 15, "праща": 8}` —
  匹чинг по подстроке имени предмета (данные, не if-цепочки). Обычное оружие range=1.
- `Combatant.range` (клетки). `from_pc`: взять лучшее оружие из сумки; если имя матчится
  ranged-таблице — range из неё, кость из качества как сейчас.
- Монстры: в бестиарии у части атак `attack.name` = Longbow/Shortbow/Sling/Javelin…
  Составь маппинг имён атак → range (данные в model.py); иначе 1.
- `engine.act_attack`: дистанция ≤ range; если range>1 И есть враг вплотную (dist 1) —
  помеха (как dodge). Крит/резисты как есть.
- ИИ (`ai_turn`): ranged-юнит с врагом вплотную — отойти на 2-3 клетки если можно, иначе
  стрелять с помехой; ranged вдали — стоять и стрелять.
- UI: клик по врагу в пределах range = выстрел (уже работает через act_attack); подсказка
  «дальность N» в панели.
- Луки в мире: добавь «лук»/«арбалет» в пару ROLE_RECIPES (охотник/лавочник) и в wares
  генерацию — чтобы покупались.
**Приёмка.** Тест в tests/combat: лучник бьёт с 10 клеток; с врагом вплотную — с помехой
(статистически: сид, где обычный ролл попадает, а мин-двух — нет). Себе купить лук в
игре → в бою стрелять.

### T4. NPC-партии в вылазках: перестать вечно проигрывать
Сейчас `from_npc` даёт hp=10 и «кулак» 1d6 — дуэты ложатся от стаи гоблинов (проверено:
0 побед за 4 утра). Сделать честно из данных NPC:
- `from_npc`: hp = `PB.npc_hp_base(8) + con_mod*2 + round(brave*4)`; оружие — лучшее из
  инвентаря NPC (как у pc: качество→кость, ranged-таблица); ac = 10+dex_mod (есть).
- `_npc_delves`: партия = 2-3 (по смелости), брать с собой стражника/охотника в приоритете
  (роль из данных).
**Приёмка.** Скрипт: 10 симуляций утра → хотя бы ~половина вылазок побеждает CR 0.75.

### T5. Гильдия: 5 рангов + удостоверение-предмет + проверка лжи (SLICE В6.3)
**Данные.** В PB (или отдельной таблице `GUILD_RANKS` рядом с PB):
`[{"name": "Медь", "cr_max": 1.0, "need": 0}, {"name": "Бронза", "cr_max": 2, "need": 2},
{"name": "Железо", "cr_max": 4, "need": 5}, {"name": "Серебро", "cr_max": 8, "need": 9},
{"name": "Золото", "cr_max": 99, "need": 14}]` — need = закрытых заказов всего
(прогрессивно). Имена/пороги можешь поправить, но структура — данные.
**Удостоверение.** Предмет (items): kind="badge", surface.name «Жетон гильдии (Медь)»,
hidden.owner = "pc"|pid, hidden.rank = 1..5. Выдаётся при вступлении (первое обращение к
доске — бесплатная Медь). Повышение: closed_jobs (flag `guild_closed|pc`) достиг need
следующего ранга → распорядитель меняет жетон (старый изымается, новый предмет).
**Гейт заказов.** `/api/play/board_take` и `/delve`: требуется жетон В СУМКЕ; ранг жетона
ограничивает CR заказа (cr ≤ cr_max ранга). Заказы выше ранга видны, но «не по чину».
**Проверка лжи (чужой жетон).** Если hidden.owner != "pc": бросок игрока d20+cha_mod
(Deception) против d20+wis_mod распорядителя (Insight) — распорядитель = работник гильдии
(его mech из пула). Провал: жетон конфискован (удалён из сумки), flag
`guild_mark|pc` = чёрная метка: доска недоступна, пока не искупишь (взять и закрыть заказ
«испытание» без награды — предложи механику попроще и реализуй). Успех: работает, но
`guild_closed` пишется владельцу жетона (не тебе) — ранг не растёт. Смерть NPC-владельца
(dead-флаг) делает жетон «ничьим» — работает без проверки.
**UI.** В карточке гильдии: твой ранг (по жетону в сумке), прогресс до следующего
(закрыто M из need). Бросок лжи — через карточку кубика (поле dice в ответе).
**Приёмка.** TestClient-сценарий: вступил → Медь; закрыл 2 заказа → Бронза (новый жетон);
украл чужой жетон (inv_move) → взятие заказа кидает Insight-проверку, провал конфискует.

### T6. Многоэтапные контракты (SLICE В6.1)
**Модель.** В data контракта: `steps: [{kind, want, target, target_name, where}, ...]` +
`step: 0`. Старые одношаговые = steps из одного элемента (миграция: при чтении контракта
без steps — обернуть сам в один шаг; не мигрировать БД).
**Проверка.** Предикаты (`_contract_on_move/talk/death`, give-путь в `_attempt`) проверяют
ТОЛЬКО текущий шаг; шаг закрыт → step+=1, нарратив «шаг такой-то готов» (сухо, из данных);
все шаги → текущая выплата `_contract_complete`.
**Генерация.** В `_CONTRACT_SYS` разреши LLM вернуть `steps` (1-3 шага, каждый из тех же
видов; пример в промпте: «принеси травы (bring) → отнеси зелье жене мельника (deliver)»).
Валидация каждого шага как сейчас (want из реального мира, target из знакомых и т.д.);
невалидный шаг — отбросить контракт целиком.
**UI.** Журнал дел: «шаг 2/3: отнести зелье…» + галочки пройденных.
**Приёмка.** Тест: двухшаговый контракт bring→deliver закрывается только после обоих
шагов, выплата одна, журнал показывает прогресс.

### T7. Доска-столб на площади (SLICE В6.2 — цель из канвы)
Отдельная ТОЧКА на карте (не здание): узел площади (`city.plaza` или ближайший к центру
key_point — выясни, что даёт citygraph; НЕ менять генератор — выбери узел данными).
- Рендер: значок-столб на карте (маленький svg-маркер в `_build_geom` keys-слое, bid
  `"board:plaza"`), виден сразу (не под туманом — столб заметен).
- Контент: объявления = контракты NPC (те, что сейчас предлагаются только в разговоре по
  доверию) публикуются сюда агендами: раз в утро 0-2 объявления от случайных placed NPC
  с активной агендой (переиспользуй генератор контрактов, giver = автор объявления).
  Плюс дубль гильдейских clear-заказов «спроси в гильдии».
- Взятие: подойти к столбу (`enterable` не нужен — просто сцена узла показывает
  «объявления» списком) → «взяться» = обычный accept.
- NPC-прохожие: утром (в `_apply_routine`) 0-1 незанятый NPC с подходящей ролью берёт
  объявление и закрывает его авторезолвом/симуляцией (bring/deliver — просто таймер
  «через день закрыто», clear — уже есть боевой авторезолв).
**Приёмка.** Утро → на столбе 1-2 объявления; игрок берёт и закрывает; на следующее утро
часть объявлений закрыта NPC (новость на столбе).

### T9. Предметы: редкость + пул + материалы (SLICE §5, В5.1-5.3) — большой
**T9a. Ось редкости.** В фактшите предмета поле `rarity`: common|rare|epic|unique
(данные-таблица весов спавна в PB или items/data). item_smith получает подсказку редкости
и усиливает флейвор/moды соответственно. Цена: множитель за редкость (PB). `unique`:
таблица `unique_spawned(world_id, item_key)` в live.db — уникальный предмет, однажды
заспавненный в мире, больше НЕ выпадает из пула (item_key = стабильный ключ по имени).
**T9b. Пул предметов мира.** Таблица `item_pool(world_id, item_id, weight)` в live.db:
при создании мира — сид-набор из ~30 предметов (item_smith по ролям городка, офлайн-часть
можно и в общий контент-пул worlds.db — реши по вкусу, задокументируй). Лут/награды/
редкий спавн тянут ИЗ ПУЛА (с весами и фильтром уникальных), новые предметы (крафт,
трофеи) ДОБАВЛЯЮТСЯ в пул мира.
**T9c. Материалы.** Таблица данных `src/aidnd/items/materials.json`: узлы-материалы
(руда, слиток, кожа, доска…: каждый — предмет kind="material") и рёбра-переходы
{from, to, tool, place_service, skill_gate, time_min}. Крафт = путь по графу:
`craft.py` новый резолвер `craft_path(have, want)`; ROLE_RECIPES переписать поверх графа
(рецепт = финальное ребро). Игрок: «сделай/скуй X» через _attempt → гейты (инструмент,
место с нужным service, материалы в сумке) → время → предмет.
**T9d. Спавн.** События: закрытие логова → 1 rare+ трофей в пул мира и на рынок
(инвентарь торговца); «караван» — раз в N дней (данные) торговцу подсыпается 2-3 предмета
из пула. Случайность: малый шанс (PB) на утреннем тике.
**Приёмка.** Уникальный предмет не дублируется; крафт по графу с гейтами работает
(руда→слиток у кузнеца с инструментом); у торговца после зачистки логова появился трофей.

### T10. Вывески по пути + прерывание пути (SLICE В2.2, В2.4)
**T10a. Вывески.** В `/api/play/move`: маршрут (список узлов) уже строится. Если путь
проходит через узел НЕЗНАКОМОГО (не в `_seen()`) ключевого здания — ОСТАНОВИТЬ движение на
этом узле: ответ `{stopped: "sign", sign: {bid, name}, remaining: to}`; UI: нарратив
«вывеска: „X“» + кнопки [занести на карту → mark_seen + продолжить] [дальше → продолжить].
«Продолжить» = повторный move к исходной цели (UI хранит цель).
**T10b. Событие-прерывание.** При движении, на промежуточных узлах с людьми: дешёвый
скоринг без LLM — если у кого-то из присутствующих эмоция anger/fear > порога (PB) или
активная агенда с act-шагом — прервать путь: короткая сцена (1 live-тик этого узла) +
[вмешаться = остаться] [мимо = продолжить]. Порог подбери так, чтобы срабатывало РЕДКО
(< 1 раза на длинный маршрут).
**Приёмка.** Путь через город мимо незнакомой кузницы прерывается вывеской; кнопка
заносит метку; «дальше» доводит до цели. Событийное прерывание срабатывает на
подготовленной сцене (форс: задать NPC anger=0.9).

### T11. Суб-локации зданий (SLICE В2.3)
Мини-граф внутри здания из фактшита `sub_rooms` (name/kind/access/features/contents):
- состояние `_S["room"]` (None = основной зал); «спуститься в подвал»/кнопки комнат;
- access: public — свободно; staff — гейт (работник пустит по доверию/роли, иначе
  скрытность DC из PB); locked — ключ (key-предмет здания уже существует); hidden —
  виден только после успешного «осмотреться» (lvl 2);
- контейнеры: у контейнера в фактшите есть `where` — привяжи выдачу `_building_containers`
  к текущей комнате (контейнеры зала видны в зале, подвальные — в подвале);
- live-прослойка: люди пока остаются «в здании» (комнату им не назначаем — v2);
- UI: строка комнат в карточке локации (текущая подсвечена), кнопки-переходы.
**Приёмка.** Таверна: зал → подвал (staff: не пустили без доверия; скрытность — бросок
кубика в карточку) → сундук в подвале лутается только из подвала.

### T12. Ключевых зданий 12 (вторая питейная и пр.)
`CityParams(key_buildings=12)` в `_play()`, `_SIGNIFICANT` дополнить хинтами 10-12
(«Игорный дом», «Баня», «Вторая таверна» — типы уже есть в пуле). Проверь `_guild_bid`
остаётся гильдией. Существующие миры (placements по 9 зданиям) сломаются по количеству
работников — это ок: дев/тест-миры можно стереть (`rm data/live.db` локально; на проде
только тестовые аккаунты — сотри их миры через destroy_world). НЕ трогать пул.
**Приёмка.** Новый мир: 12 ключевых, две питейные (routine: вечерняя толпа делится).

### T13. Живость NPC: эхо-темы, кэп реплик, адресность (дефолты из тестов)
В `_live_tick`/`decide_hybrid`-контексте:
- **Эхо.** Собери множество нормализованных тем реплик ЭТОГО тика (леммы не нужны —
  первые N слов текста / ключевые слова); в ctx каждому следующему решателю — строка
  «в зале уже говорили о: …, не повторяй»; плюс пост-фильтр: если реплика почти дублирует
  (общий префикс/жаккар > порога PB) уже принятую в этом тике — заменить действие на
  «слушает» (без реплики).
- **Кэп.** ≤ `PB.say_cap_per_tick` (3) реплик за тик: решения обрабатываются в случайном
  порядке — после 3 принятых say остальные say глушатся в дела (лог: жест/действие).
- **Адресность.** Если NPC обратился к другому ПО ИМЕНИ (to=pid), у адресата в следующем
  тике ctx-строка «к тебе обратился X: „…“ — ответь или отмахнись» (и приоритет say).
  Механика «к тебе обратились» уже есть для игрока — обобщи на NPC.
**Приёмка.** 4 тика таверны: нет 4 одинаковых «вложись в дельце», говорят ≤3 за тик,
на прямой вопрос по имени в следующем тике есть ответ адресата (проверить в feed).

### T14. Стартовые отношения: убрать uniform −0.10

только к игроку-чужаку через appraise, не константой. Проверь `_weave_ties` и
`NpcState.rel()`. **Приёмка.** Свежий мир: у случайной пары NPC без связей aff == 0.
