## P0 — Стоимость и латентность: LOD-бюджет толпы не работает

**Симптом:** в таверне каждый тик = ~130 вызовов `npc_mind` (души == LLM-актёры в 50/50
замеренных тиков; ~6.5k вызовов за день плейтеста; /act и /say по 16–29 сек).

### F1. Инверсия порога «обязан думать»
- Корень: `world.py:966-967` — нужда ≥0.65 даёт impulse = 1.2+hot ≥ **1.85**, а
  `live_must_impulse=1.5` (config.py) — исключение из капа ловит почти всех;
  `live_active_cap=6` никогда не срабатывает.
- Фикс (тюнинг, не новый гейт — бюджет уже задуман): развести шкалы. Либо поднять
  `live_must_impulse` выше пола нужды (например 2.2 — реально «обязаны» остаются беседа с
  игроком, реактивные импульсы, agenda-события), либо дать нуждовому импульсу собственный
  потолок < must-порога. Не-выбранные NPC живут дешёвым кодовым путём (как задумано ротацией).
- Приёмка: лог `─── ТИК … душ=X · LLM-актёров=Y` показывает Y ≤ 6+реактивные в толпе 100+;
  живой плейтест — сцена не омертвела (слухи/дела продолжаются через ротацию).

### F2. /act и /say не должны синхронно гонять всю толпу
- Корень: `loop/tick.py:16-52` — `_world_tick()` (полный `_live_tick`) вызывается в КОНЦЕ
  обработки /act и /say; /move//talk уже используют `_world_tick_fast()`.
- Фикс: /act и /say → fast-путь; реакция толпы уезжает в ближайший клиентский /live
  (клиент и так его стримит). Ответ игроку несёт только его собственный narrator-вызов.
- Приёмка: латентность /act < 8 сек в толпе; реакция мира приходит следующим /live.

### F3. Проверить LIVE_CONCURRENCY
- `world.py:1030` ThreadPoolExecutor(max_workers=config.LIVE_CONCURRENCY): если мал —
  остаточная толпа сериализуется волнами. После F1 подобрать значение (замер).

## P1 — Играбельность: «знаю место — не могу дойти»

**Симптом (фаза D):** Эмса поделилась дорогой, метка `seen|house:9:310_372` стоит, journal
told-row есть — но «иду к дому Медовара» не двигает игрока: 30 узлов вручную, бой не состоялся.

### F4. Move-резолвер должен знать открытые здания
- Корень: `handlers/freeform.py:164-178` — `verb=move place=…` резолвится ТОЛЬКО по
  `_S["geom"]["keys"]` (ландмарки); обычные дома невидимы для «иду к …».
- Фикс: цепочка резолва: geom.keys → здания с флагом `seen|<bid>` (имя через `_binfo`,
  узел — тем же путём, каким geo.direction_line находит узел цели) → иначе честное
  «Ты не знаешь, где это. Спроси у людей.» (уже есть).
- Приёмка (юнит+живой): после share NPC → /act «иду к дому Медовара» → goto=<узел дома> →
  фронт доводит; тест на нераскрытое здание по-прежнему отказывает.

### F5. Инцидент-контракты несут привязку к месту
- Корень: `ct:inc:*` хранит цель прозой («твари в подполе — дом семьи Медовар»); Медоваров
  шесть; incidents-генератор ЗНАЕТ дом жертвы, но не пишет его.
- Фикс: писать `bid`+`node` в data контракта; board/pitch добавляют direction_line (готовый
  форматтер geo.py); взятие с доски ставит метку (`_mark_seen(prov="told")`) — тот же
  консеквент, что у geo-share.
- Приёмка: свежий инцидент → board_take → метка на карте + goto-путь доступен через F4;
  живой прогон закрывает контракт боем.

## P2 — Хроника: рыночный гул стирает личную историю

**Симптом:** journal = 2000×event, min(gt)=3304 в мире от 1180 — кража, встречи, told-строки
вытеснены за сутки у рынка.

### F6. Kind-aware прунинг + гашение гула
- Корень: `worldgen/store.py:250-257` — прунит старейшие без разбора kind
  (`PB["journal_cap"]=2000`, config.py:230).
- Фикс: (а) прунить только `kind=event` до event-капа; person/place/quest — свои щадящие
  капы (или не прунить: их сотни, не тысячи); (б) journal_feed не пишет каждую реплику торга —
  только состоявшиеся сделки («отсчитывает N зм…»), торговые выкрики дедупятся за тик.
- Приёмка: юнит на прунинг по kind; живой день у рынка — person/place/quest строки первого
  дня живы, event-шум ограничен.

## P3 — Нарратив обещает, механика не делает (худший класс трещины)

### F7. Подбор предмета: нарратив без доставки
- Симптом (крафт-тест): «…хватаешь рукоять ржавого ножа… ощущая холод металла» — инвентарь
  пуст. Нарратор описал ДО валидации механики.
- Корень: freeform take-путь (`handlers/freeform.py` verb=take / arbiter) — рассказ идёт даже
  когда предмет не материализован в зоне.
- Фикс: порядок — механика решает (предмет есть в зоне/контейнере → перенос в инвентарь;
  нет → честный отказ), нарратив рендерит РЕЗУЛЬТАТ. Никогда наоборот.
- Приёмка: юнит: take существующего → инвентарь+нарратив; take выдуманного → отказ без
  сенсорной прозы. Живой прогон.

### F8. Вход для крафт-программы (идёт отдельной сессией — mint-план)
Не чинить здесь, передать в программу крафта как требования плейтеста:
- материалы не добываются фриформом («подбираю щепки» → «Этого нет под рукой»);
- парсер требует невозможной точности («Не пойму, что смастерить — назови вещь»),
  рецепты нельзя ОТКРЫТЬ игрой;
- commission: пустой вызов отвечает «нет такого» без подсказки формы; артизан
  (Ярм Кривой) упоминается речью, но недостижим как механика;
- разбитая кружка consumed, осколки не появились (транформация без выхода).

- **Деяния-шаблоны:** «Иду к очагу / Подхожу к стойке / Цокаю языком» ×50 — метрономный гул

  туре, остаётся.
